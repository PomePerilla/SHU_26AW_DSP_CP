# 长时波形、完整会话与历史试听

日期：2026-10-30。入口：项目根目录 `launch.cmd`。本轮未生成安装包或公开发布。

## 使用方式

启动实时处理后，默认保存完整会话。默认目录 `data/recordings/`，可从第四个“设置”页更改目录，或关闭下一次采集的自动保存。四路16kHz、单声道FLOAT WAV总计约0.92 GB/小时；旧录音由操作者管理，不自动删除。

波形默认显示10秒，设置可选2、5、10、30、60、300、600秒。横轴是从本次会话开始计时的秒数。默认锁定波形纵轴−1至1、频谱纵轴−100至0 dBFS，只允许横向拖动和缩放；设置中可分别解锁。原生自动缩放按钮与坐标菜单隐藏。

- **跟随实时**：显示最新窗口。手动拖动或缩放后取消跟随，但录音和实时处理继续。
- **显示整段**：查看本次全部已保存数据。未开启录音时，只能查看仍在30秒内存缓存中的部分。
- **复位视图**：恢复设置中的跨度、标准纵轴范围和跟随，避免缩放后找不到曲线。
- **会话**：停止采集后打开历史会话，查看保存时间、时长和完成状态，或打开录音目录。
- **历史试听**：播放/暂停、拖动进度、选择原始或处理后音轨；底部音量调节试听。历史频谱按播放位置计算。
- **返回实时**：关闭历史播放、清空旧来源读数，恢复实时界面。历史模式禁用实时音效和组员操作，不重新处理或识别旧录音。

显示设置立即生效，录音设置从下次采集生效，保存于 `data/ui-settings.json`。原有“导出最近30秒”保持独立。界面移除了装饰性中文分隔符，时间、状态、操作分别布局。

## 数据与实时边界

音频回调仍只写30秒共享内存环形缓存，没有新增文件读写或等待录音进程。新增录音进程按绝对样本位置取走数据；停止音频后等待录音追到最后一帧并收尾。录音写盘失败独立提示，实时音频可继续；缓存已覆盖、异常退出或写盘失败不会补零伪装成完整录音。

每个会话目录包含 `session.json`、每10分钟一组的四路WAV，以及 `peaks-N.bin` 分层峰值摘要。四路名称为 `microphone`、`processed`、`render_reference`、`aec_residual`。索引保存设备、起止时间、样本数、分段、状态和参数变化。参数变化的 `frame` 是**请求时的缓存位置**，不是承诺在该样本精确应用；实际生效受音频控制进程轮询影响。处理后信号仍有256样本算法延迟，参考轨仍为AEC使用的上一回调块输出。

峰值摘要以256样本为基础，每4桶向上汇总。概览读取摘要，细看读取对应原始区间；单条曲线点数随像素宽度限制。摘要缺失时有界分块扫描，不整段读入内存。概览悬停显示分桶峰值，时间位置不是峰值发生的精确采样点。缺失区间用断线表示，不连接成伪连续曲线。

波形读取使用独立线程，不与声纹任务共用执行器；返回结果按来源及视图代数校验，旧会话结果不会覆盖新来源。历史播放运行在独立进程，后台线程有界预读，输出回调只取已预读样本；跳转与音轨切换有代数隔离，过期状态不会把光标拉回旧位置。

自动界面验证使用 `test_mode=True`，默认不录制真实音频、不写用户设置。实际运行仍默认自动保存。

## 联测发现与修复

首次联测在约38秒发现Windows索引替换遭遇短暂拒绝访问：界面读旧索引时，后台原子替换文件可能被拒绝。录音正确报告失败，实时音频仍继续。随后对索引读写加入有界重试，并以200次并发写入/持续读取的回归测试确认；重新运行完整120秒联测通过。首次失败证据保留在 `hardware-before-index-retry.json`，最终结果见 `hardware-120s.json`。

重测包含取消跟随浏览旧窗口、显示整段、恢复60秒跟随，然后停止保存、重新打开及历史输出。整个测试输出静音，麦克风录音仅存于临时目录，退出后已删除，未留下真实录音或注册组员文件。

20–120秒的进程私有提交量采样中，GUI约增加0.61 MiB，音频约增加0.03 MiB，录音进程基本稳定。这支持本次时段内没有随录音长度持续增长的原始音频堆积；不能代替数小时长期稳定性验证。记录器仅持有当前块和不足一组的峰值尾部，预读与绘图请求有界。参数事件和分段索引仍随操作者调整及分段数增加。
